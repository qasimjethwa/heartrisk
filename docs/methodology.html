HeartRisk / Methodology

How the estimate is made

1 · Data

The model was trained on a public Framingham-style dataset: 4,240 rows, 16 columns, target TenYearCHD (did the person develop coronary heart disease within 10 years). Overall prevalence 15.2%. The file used was downloaded from the public GitHub mirror GauravPadawe/Framingham-Heart-Study (framingham.csv, SHA-256 2c0e57dc0361b420becf1facec0a054af06c420eae0ae2faf0fdc8591fadb018), which itself points to the NHLBI Biolincc teaching data and to the Kaggle copy of the Framingham data. Full provenance, including the licence caveat, is in DATA_PROVENANCE.md in the repository.

Missing values in the source: glucose 388 rows, education 105, BPMeds 53, cigarettes/day 29, BMI 19, heart rate 1. Rows were not silently dropped for training; missing values were median-imputed inside the pipeline (see below).

2 · Features

Fourteen features were used: male, age, currentSmoker, cigsPerDay, BPMeds, prevalentStroke, prevalentHyp, diabetes, totChol, sysBP, diaBP, BMI, heartRate, glucose. education was deliberately dropped — it is not a health input in the simulator, and using it as a predictor would add a social variable with no clinical meaning in this product.

3 · Leakage control

  • Stratified 80/20 train/test split, random_state=42 (train 3,392 rows, test 848 rows; prevalence 15.2% in both).
  • Imputation (median) and scaling (mean/std) live inside an sklearn Pipeline, fitted on the training split only. The test split was used once, for evaluation.
  • Stratified 5-fold cross-validation on the training split for the CV ROC-AUC figures.
  • Threshold 0.5 was used only for the confusion matrix and F1. The shipped product shows probabilities, not a yes/no label, because a 0.5 threshold on a 15% prevalence outcome is a poor summary.

4 · Models compared

Logistic regression (median imputation + standard scaling, C = 1.0) versus random forest (median imputation, 300 trees, min_samples_leaf = 2). Both were evaluated identically. Logistic regression was selected: higher test ROC-AUC (0.702 vs 0.646) and CV ROC-AUC (0.732 vs 0.719), exact export as coefficients + scaler, and direct explainability. Random forest would have exported as hundreds of trees with worse test performance.

5 · Calibration

Sigmoid (Platt) calibration was tried in prototyping and improved the Brier score by only about 0.0004 (0.1213 → 0.1209), so it was not shipped — shipping a 5-model calibrated ensemble would have complicated the browser export and parity check for negligible gain. Instead the test-set calibration bins are published in model.json and rendered on the Science section, so any miscalibration is visible: low bins track the observed rate closely; the highest bins are based on very few test cases and are noisy.

6 · Browser export and parity

src/train.py exports the logistic regression as docs/model.json: feature order, training medians, scaler mean/scale, coefficients and intercept. docs/model-core.js implements exactly the same formula (median imputation → scaling → dot product → sigmoid). src/parity.js compares the JavaScript output with sklearn's predict_proba on 30 held-out rows, 3 illustrative profiles and 4 edge cases; the full report is in PARITY.md. Tolerance was 1e-4; the achieved maximum difference was about 1e-16.

7 · What-if and top-factor calculations

Both are computed by re-running the exported model with one input (or, for smoking, the status + cigarettes pair) changed, everything else held constant. Top factors replace a factor by its reference value (training median, or absent/non-smoker for binary factors) and report the probability difference in percentage points. These are model associations. They are not causal effects, and they do not account for how factors move together in real life.

8 · What the model cannot do

  • Distinguish former smokers from never-smokers (the source has no former category).
  • Represent populations outside a mid-20th-century Framingham cohort, ages 32–70.
  • Use family history, diet, activity, genetics, medication details or any examination finding — none are in the source data.
  • Give a personal diagnosis or a safe target for any individual value.

9 · Privacy

The demo makes no external requests: no fonts, no analytics, no chart library, no backend. Inputs exist only in page memory. The only file fetched is model.json from the same site. There is no account and no persistence of any kind.

10 · Reproduce it

python3 src/train.py retrains both models and rewrites docs/model.json and METRICS.md. node src/parity.js re-checks browser parity. Serve docs/ with any static server (python3 -m http.server --directory docs 8000) — opening index.html directly from disk will block the model file fetch in most browsers.
