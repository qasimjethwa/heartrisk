HeartRisk / Methodology

How the estimate is made

1 · Data

The model was trained on a public Framingham-style dataset: 4,240 rows, 16 columns, target TenYearCHD (did the person develop coronary heart disease within 10 years). Overall prevalence 15.2%. The file used was downloaded from the public GitHub mirror GauravPadawe/Framingham-Heart-Study (framingham.csv, SHA-256 2c0e57dc0361b420becf1facec0a054af06c420eae0ae2faf0fdc8591fadb018), which itself points to the NHLBI Biolincc teaching data and to the Kaggle copy of the Framingham data. Full provenance, including the licence caveat, is in DATA_PROVENANCE.md in the repository.

Missing values in the source: glucose 388 rows, education 105, BPMeds 53, cigarettes/day 29, BMI 19, heart rate 1. Rows were not silently dropped for training; missing values were median-imputed inside the pipeline (see below).

2 · Features

Fourteen features were used: male, age, currentSmoker, cigsPerDay, BPMeds, prevalentStroke, prevalentHyp, diabetes, totChol, sysBP, diaBP, BMI, heartRate, glucose. education was deliberately dropped — it is not a health input in the simulator, and using it as a predictor would add a social variable with no clinical meaning in this product.

3 · Leakage control and held-out design (supersedes the old 80/20 split)

  • Stratified 60% train / 20% calibration / 20% test, random_state=42 (train 2,544 rows, calibration 848 rows, test 848 rows; prevalence ~15.2% in every split). The old 80/20 numbers are superseded and must not be quoted alongside the new ones.
  • Imputation (median) and scaling (mean/std) live inside an sklearn Pipeline, fitted on the training split only.
  • Hyperparameters were tuned by stratified 5-fold cross-validation on the training split only, scoring ROC-AUC.
  • Calibration was fitted on the calibration split only, never on test. The calibration method was chosen by 5-fold cross-fitted evaluation within the calibration split, not by test results. Test was evaluated once, finally, for every candidate and variant.
  • Threshold 0.5 was used only for the confusion matrix and F1. The shipped product shows probabilities, not a yes/no label, because a 0.5 threshold on a 15% prevalence outcome is a poor summary (shipped recall at 0.5 is only 5.4%).

4 · Models compared (same splits, same metrics)

Regularized logistic regression (C and class_weight tuned by CV), random forest (tuned modestly by CV), HistGradientBoosting (sklearn, tuned modestly by CV; XGBoost was not installed and was not added silently), and an unregularized logistic baseline (C=1e6). The full test table — ROC-AUC, PR-AUC, accuracy, precision, recall, specificity, F1, confusion matrix, Brier, log loss, calibration intercept and slope, for uncalibrated, sigmoid and isotonic variants — is in EVALUATION.md and summarised in the table rendered below from model.json.

5 · Calibration — and why a percentage is not automatically trustworthy

If 100 people are given a predicted risk of 20%, a calibrated model means about 20 of them should experience the outcome over 10 years, on average, in an appropriate population. It will not be exactly 20 every time; what matters is agreement across the whole range of risks. A model can rank well (ROC-AUC 0.704) and still give untrustworthy percentages — the tuned logistic regression proved it: its raw probabilities had a test Brier score of 0.207 and a calibration intercept of −1.63, because class_weight='balanced' inflates them. Sigmoid (Platt) calibration on the logit scale, fitted on the calibration split only (a=−1.6183, b=0.8737), restored them: test Brier 0.1205, intercept −0.109, slope 0.942. Isotonic calibration was tied on cross-fitted Brier but worse on cross-fitted log loss and unstable on test, so it was not shipped. Calibration intercept/slope here mean a logistic regression of the observed outcome on logit(predicted probability), fitted on test for reporting only; perfect is intercept 0, slope 1. For isotonic step outputs that slope is unstable and is never used alone. The shipped calibration curve is charted below from model.json (decile bins, n≈85 each).

6 · Browser export and parity

src/train.py exports the shipped model as docs/model.json: feature order, training medians, scaler mean/scale, coefficients, intercept, and the sigmoid calibration parameters a/b. docs/model-core.js implements exactly the same formula (median imputation → scaling → dot product → sigmoid → sigmoid calibration). src/parity.js compares the JavaScript output with sklearn's calibrated probabilities on 30 held-out rows, 3 illustrative profiles, 4 edge cases and 6 calibration cases (43 total); the full report is in PARITY.md. Tolerance was 1e-4; the achieved maximum difference was about 8e-17.

7 · What-if and top-factor calculations

Both are computed by re-running the exported model with one input (or, for smoking, the status + cigarettes pair) changed, everything else held constant. Top factors replace a factor by its reference value (training median, or absent/non-smoker for binary factors) and report the probability difference in percentage points. These are model associations. They are not causal effects, and they do not account for how factors move together in real life.

8 · What the model cannot do

  • Distinguish former smokers from never-smokers (the source has no former category).
  • Represent populations outside a mid-20th-century Framingham cohort, ages 32–70.
  • Use family history, diet, activity, genetics, medication details or any examination finding — none are in the source data.
  • Give a personal diagnosis or a safe target for any individual value.

9 · Privacy

The demo makes no external requests: no fonts, no analytics, no chart library, no backend. Inputs exist only in page memory. The only file fetched is model.json from the same site. There is no account and no persistence of any kind.

10 · Reproduce it

python3 src/train.py retrains and re-evaluates all models and rewrites docs/model.json, METRICS.md and EVALUATION.md. node src/parity.js re-checks browser parity. Serve docs/ with any static server (python3 -m http.server --directory docs 8000) — opening index.html directly from disk will block the model file fetch in most browsers.
